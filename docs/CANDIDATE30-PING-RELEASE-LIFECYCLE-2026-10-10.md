## Changed behavior

Button-down only arms the native ConsolePort account ring. No ping or macro is
dispatched at press or by the artwork timer. A selected/sticky release uses the
native Main/Commit and secure macro dispatcher once. A release with no selected
type supplies one contextual aimed macro after native Commit closes the ring.
The secure PreClick wrapper returns its native button alias AND a non-nil message,
so Blizzard's actual wrapped-click post-body runs before action dispatch.

Tap sends on release with no selector artwork. Holding reveals the actual native
account ring after 0.15 seconds, with no initial ping. A neutral hold release also
sends the aimed contextual fallback: this design does not pretend that artwork
timing is a privileged tap/hold discriminator. Sticky/deflected-stick quick
releases retain native selection and can choose a typed aimed ping before the
artwork delay. Native owner/state/cancellation and other actions are retained;
the fallback applies only to this opener's valid empty selection, never a native
custom/nested/selected action or a stale/cancelled release.

## Lifecycle diagnosis and repair

The adapter previously cancelled, released claims and rebuilt native actions at
every ordinary Refresh, even during a held gesture. That interruption is reproduced
with the actual native backend/frontend/secure wrappers. Stable declarations now
reuse the existing setup without cancelling, changing its reveal deadline or
rebuilding pooled actions. Changed keys, disabled features or failed qualification
still release the owned overrides. Shared-ring edits remain native and are not
reseeded. Naming collisions still fail closed.

A dedicated unprotected frame now owns the cosmetic reveal timer rather than a
HookScript on the shared header's OnUpdate. Each gesture begins/ends its own
artwork lease and restores a nonzero previous alpha. A transient nil controller
sample no longer instantly clears focus and strands alpha zero. A definitive
device change or 0.25-second sustained missing state releases the native camera
focus; public callbacks never alter protected visibility/attributes in combat.
The user's precise live rendering failure is not established as a single cause;
these fixes address the evidenced interruption and fragile artwork lifecycle.

The user tested a direct C_Ping.SendMacroPing call and supplied a screenshot of
Blizzard's ForceTaint_Strong blocked-action popup. The chat pcall result was true,
so pcall success alone is not proof of permission or a sent ping. No such direct
API calls enter the implementation. The restricted environment has no GetTime
and deliberately omits GetAlpha. Clock/alpha are cosmetic only; protected pings
remain on hardware release through the native macro dispatcher.
