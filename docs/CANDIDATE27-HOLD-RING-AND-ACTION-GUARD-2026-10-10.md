## Remove automatic restoration; preserve native edits

The user subsequently reports dragonriding edits being reverted: dropped spells
were not retained and removed spells came back. The installed `/cpf action-recovery
off` toggle alone did not immediately clear the behavior; a logout/login did.
The user then reports further intermittent reversion while rearranging. A runtime
reset helped temporarily; it did not establish the original storage writer.
The user's request to undo the bar interference supersedes the proposed stronger
automatic recovery. No candidate.27 code had been deployed during these reports.

Automatic slot restoration is removed entirely from candidate.27: no emergency
seed, spell pickup, PlaceAction, cursor clearing or queued restoration. The
compatibility Refresh entry point only cancels stale pending state, marks recovery
disabled and reports diagnostic status. `/cpf action-recovery on` cannot revive
it. Historical saved snapshots/attempts and deployment backups remain available.
The addon can observe action storage; native editing remains game-owned.

Source inspection finds separate runtime editing defects in TemporaryRouting:

- Each refresh reapplied the same native binding declarations, overwriting direct
  button edits even when bindings had not changed. Reapply only changed binding
  declarations; still capture real character/binding changes and native rebuilds.
- Native removal of a direct spell/item/macro cleared LAB fields but left the
  companion's cached ordinary kind/action intact. UpdateState then resurrected
  the removed action. Extend the actual native OnDragStart attribute (which is
  outside ConsolePort's Env table) to clear that cache in the native non-action
  branch, and retain its original body for disable/restore.
- Native drag/drop can start after mouse-down armed the held-action latch.
  Release that latch and resolve the current page when a valid native edit begins,
  so a drag after mounting cannot target a stale ordinary binding. Retain native lock/drag-disable early returns.

Native action-slot drops/removals continue to target the resolved dragonriding,
vehicle, possession, quest, override or temporary slot; they must survive refresh
and page transitions. Unavailable overflow cells on a six-button temporary page
reject drops without consuming them or storing them as ordinary bindings. The
L2+R2 routing, native input/casting and accepted ground placement remain.

Keep bounded passive pickup/place and talent-loadout API observers plus bar,
level-up and trait event context. Retain up to 40 recent events with stack/writer
context; hooks neither replace APIs nor change returns. Good diagnostic snapshots
remain GUID/spec/saved-config owned and do not accept majority loss/scramble as a
new good view. Engine-only writes may still lack a usable addon stack. These are
read-only diagnostics, not an action-slot repair service or proof of the original
quest-loss trigger. TalentLoadoutManager remains unchanged and unblamed.
