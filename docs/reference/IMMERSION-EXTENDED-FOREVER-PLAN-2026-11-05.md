## Functional design

1. **Client and load ownership.** Use a Forever interface declaration and an explicit WOW_PROJECT_CAMELOT client check before registering hooks/events. Immersion is required; Pawn is optional. Optional dependency order must put the addon after Pawn code but before PLAYER_LOGIN, allowing observation of Pawn's actual initialization boundary. Missing/incompatible Pawn disables arrows while leaving positioning available. Unsupported clients perform no work. Do not infer Pawn readiness merely from a loaded flag.
2. **Pawn arrows.** Add only an overlay texture using the native bags-greenarrow atlas to current visible item rewards/choices owned by Immersion's current reward-button list. Read the full link from GetQuestItemLink using the button's native type/ID. Call the public budgeted PawnShouldItemLinkHaveUpgradeArrow(link, true), leaving level checks, scales, equipment comparisons, item-level options and upgrade verdicts to Pawn. Honor Pawn's quest-advisor preference. Never score items independently or hardcode class/spec/item verdicts. BetterBags is not a dependency: disabling it must not remove this integration.
3. **Reward lifecycle.** Verify current frame/button/quest/link ownership; hide stale overlays before reuse and when the quest closes or changes. Secret/unknown values must fail closed before comparisons. True shows an arrow; false hides it; nil queues a bounded retry. Coalesce relevant item-data, equipment, Pawn-reset and specialization changes. Cancel timers on close/invalidation and cap retry work; no permanent OnUpdate or constant polling.
4. **Native interaction preserved.** Do not replace reward click handlers, select rewards, claim focus or navigate controls. No bindings, secure snippets, input interception, macros, bag ownership or UI takeover. Existing Pawn tooltips and Immersion's inspector remain their owners. The requested initial feature is summary reward arrows; importing the Retail focused-tooltip annotation feature is outside this initial scope.
5. **Required Items positioning.** Adapt the existing Retail progress bridge to standalone ownership. Post-hook native QUEST_PROGRESS/layout events and wait past Immersion's own second measurement. For the eligible visible Required Items state, measure Progress height and call native TalkBox:SetExtraOffset((height + 48) * elementscale). Preserve the saved resting X/Y, root/subframe scales, anchor and all Immersion preferences. The repair applies only to bottom anchoring, enabled native offset animation, ordinary non-nameplate mode and finite usable dimensions. Avoid redundant writes.
6. **Position guards and invalidation.** Do not reposition during combat or Edit Mode; re-evaluate the still-current eligible dialog afterward. Cancel queued work on hide, quest/state/owner change. Preserve native layout for top anchors, disabled offset behavior, unrelated gossip/details/reward frames and unsupported contracts. Do not add arbitrary pixel patches for other frames without a demonstrated cause. This implements the known Retail Required Items correction, not a promise to solve every possible layout difference.
7. **Configuration and diagnostics.** Keep this first addon stateless: no SavedVariables, no installer-driven WTF writes and no settings migration. Provide a read-only status command reporting client/capabilities/readiness, current feature status and bounded work counters; do not dump character/item/account data into logs. Disabling the addon returns to the upstream behavior on the next load.

## Validation before installation

8. **Source-based regressions.** Capture only the necessary current upstream source evidence inside the repo with hashes. Exercise the actual addon code and relevant native Immersion layout/button methods where feasible; model unavailable engine APIs explicitly. Reproduce missing arrows without the new addon and the native progress measurement race. Test upgrades/non-upgrades/unknown stats, level restrictions, delayed item data, quest/button reuse, close/reopen, Pawn initialization before/after binding, Pawn absent, BetterBags absent, preference disabled, differing compatible version metadata and unsupported client. Include combat/Edit Mode deferral, anchor/scale/layout guards and stale callbacks.
9. **Meaningful fault controls.** Require tests to reject premature Pawn calls, stale arrows, unbounded/repeated timers, hard dependency on BetterBags, wrong item/quest ownership, early/wrong-height positioning, leaked work after close and changes to upstream methods/preferences. Track work counts so public event bursts cannot create unbounded queries or layout writes. Lua 5.1 syntax plus offline Lua execution are necessary; neither proves engine pixels, taint or hardware timing.
10. **Delivery tooling extension.** Existing build_update/deploy_update currently force ConsolePort_Forever and a Retail root, so they cannot be used unchanged. Extend those existing entry points with an explicit standalone-addon manifest/selection for ImmersionExtended_Forever and an explicit Forever game-tree profile. Preserve the default Retail companion route and its gates. The standalone route must reject Retail roots, ConsolePort payloads, arbitrary addon names, dependency updates/retirements, WTF payloads, link/path escapes, wrong checksums, running WoW and concurrent drift. Reuse existing inventories, archive validation, backup/staging/atomic promotion and guarded rollback; do not create another installer or relax existing companion requirements.
11. **Complete checks and exact source.** Add focused runtime/ownership tests to the existing full runner and installer safety tests to existing tooling discovery. Run targeted checks while developing, then the complete Test-All.ps1 with current complete product/tool/test inventories. Update the maintained requirements/architecture/testing/delivery guidance affected by the separate addon. Commit and push only the exact tested implementation/tooling/docs/source receipts under the repository release rules; keep private WTF snapshots, backups, diffs and unrelated prior work out of source publication.
